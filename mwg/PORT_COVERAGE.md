# Port coverage

Tracks which blocks of Wesnoth's real C++ source and data this port has
translated, block by block: a function, a formula, a data table. "Ported" means
the TypeScript reproduces that block's real numbers/logic; "Simplified" means
it reproduces the shape with a stated, deliberate reduction; "Not ported" means
Wesnoth has this and this port currently does not, at all.

Update this file in the same commit as the code change, the same way
mwg-pixel-dungeon keeps its own PORT_COVERAGE.md current. This file is the
ledger of what *is*; `ROADMAP.md` is the plan for what is left, measured against
the original engine and data (`ROADMAP.md` sections 1 and 3).

## MWL data route (framework MWL plus the port adapter)

The data pipeline now runs through the framework's MWL layer instead of bespoke
extraction functions. `tools/compile-wesnoth-data.ts` only reads Wesnoth files
and emits assets; `src/adapters/from-mwl.ts` owns the translation.

### Campaign loader hardening (P3)

`[harm_unit]` is now routed through an engine hook with variable-backed damage,
filtered unit selection, death handling, and retained attack selectors. The
same unit-modification path now applies common experience, alignment, poisoned,
slowed, recruitability, name, and damage-type changes. Regeneration reduces the
compatibility report to 1,728 skips and 1,728 warnings across 398 scenarios;
there are no blocking entries.

`[replace_map]` and `[replace_map_section]` now replace full maps or terrain
fragments at runtime, including map-size dependent fog and village state.

`[modify_ai]` event actions now reach the runtime for candidate-action
enablement and positional goal/avoid directives, rather than being discarded
as unknown commands.

`[set_variables]` now reaches the runtime as a structured variable command:
`[value]` and `[literal]` children build nested objects, `mode=append` extends
existing arrays, and `[split]` builds keyed entries while scalar leaves retain
WML interpolation semantics.

`[delay]`, `[store_locations]`, `[teleport]`, and unit visibility changes now compile to runtime hooks;
delays preserve their declared duration, location storage evaluates map terrain,
ranges, radii and adjacent terrain, and teleportation uses the real movement
rules with filtered unit selection.

The WML filter implementation now also evaluates `[filter_adjacent]` and
`[filter_adjacent_location]`, including nested unit/location criteria,
`count=`, and `is_enemy`/`is_friend`; their remaining status in the older
summary row is superseded by the tested implementation in
`src/scenarios/wml-filter.ts` and `tests/wml-filter.test.ts`.

It also evaluates `[filter_vision]` against the live per-side fog state,
`[filter_ability]` against registry ids and effect tags such as `illuminates`,
and unit/event `formula=` filters through the shared expression evaluator.

Scenario `[sound_source]` and `[remove_sound_source]` actions now use MWG's
`SoundSource`/`AudioListener` distance mixer, and story-part `music=` is
emitted as a music hook before the narrator page.

Pure-return `[lua]` conditions are evaluated by the optional Pyroeis host with
WML variables and `wesnoth.game_config.random_mode`; imperative Lua and the
unimplemented `wesnoth.*` API remain deferred.

Three real bugs were fixed while landing this route:

- `Ch`/`Chw`/`Chr` were mapped to the chasm tile; they are castle tiles
  (`human_castle`, ruin, wall), and chasm codes are `Qx*`. Castles rendered as
  the chasm abyss before this.
- MWL's `id` value type rejects spaces, but many Wesnoth unit type ids contain
  them (`Drake Arbiter`). `unit_type.id` is a string in the schema, with a
  regression test.
- Every sprite was invisible in the built page. The scene used
  `Texture.from(dataUri)`, but Pixi 8's `Texture.from(string)` only reads Pixi's
  asset cache and never loads anything, so it returned no texture and `Sprite`
  silently fell back to an empty one (HUD text and `Graphics` hexes still drew,
  no console error). Textures now load through `Assets.load` with an explicit
  `parser: 'loadTextures'` (a `data:` URI has no extension for Pixi to detect),
  and the scene redraws when a load resolves. The board is also scaled to fit
  the window so the whole map is visible above the HUD.
